## Docker Compose 环境变量管理规范

为保证基础设施项目的配置隔离、安全性和可维护性，所有服务必须遵循以下规则：

### 1. 环境变量文件职责

- **根目录 `.env`**：仅存放多个服务共享的公共配置，例如时区、公共 Docker Network 名称等。
- **服务子目录 `.env`**：存放对应服务专属的配置，包括数据库 DSN、API Key、账号密码及其他敏感信息。
- **禁止在根目录和子目录中重复定义同名变量**，避免 Docker Compose `include` 的环境变量优先级导致意外覆盖。

### 2. 敏感信息管理

- 数据库 DSN、密码、API Key 等敏感信息必须归属于实际使用它们的服务。
- 不同应用必须使用独立的数据库用户和数据库，禁止多个应用共享 PostgreSQL 超级用户。
- `.env` 文件必须加入 `.gitignore`，禁止提交真实凭据到 Git 仓库。
- 应提供 `.env.example` 作为配置模板，模板中只能包含占位符，不得包含真实密钥。

### 3. Docker Compose 配置规范

- 优先使用根目录 Compose 文件通过 `include` 统一编排各子项目。
- 每个子项目维护自己的 `compose.yaml` 和 `.env`，保持配置独立。
- 使用 `env_file` 将变量注入容器，使用 `${VARIABLE}` 进行 Compose 配置插值时，必须明确变量来源。
- 不得依赖根目录环境变量覆盖子项目的专属配置。
- 公共 Docker Network、共享服务名称等基础设施配置应统一管理。

### 4. 配置修改与验证

修改环境变量或 Compose 配置后，必须执行：

```bash
docker compose config
```

检查最终解析结果，确认变量来源及配置值符合预期。

### 5. 核心原则

**公共配置全局管理，业务配置归属服务，敏感信息就近隔离，禁止重复定义，配置变更必须验证。**
